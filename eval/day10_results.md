## 决策与追问

- **4 条应关联都被追问。** 参考工单全部排第一，但第一名分数都低于关联阈值 0.45，工单也缺少相同的已知 VS Code 版本。例如 #251403 的参考工单 #241827 排第一，分数约 0.448，参考工单没有录入版本。
- **4 条应新建都被追问。** 第一名分数达到 0.25 的追问阈值。例如 #248468 报告 Linux 终端把 URL 中的冒号转义，第一名 #47816 报告 Windows 终端继续使用旧的环境变量，处理动作仍被词面相似度推到追问。
- **离线追问的覆盖有限。** 将明确在参考答案中出现的错误输出、命令、环境或复现条件分别作为信息点。固定问题关于错误输出的部分覆盖了 #262330、#275714 和 #305957 各一个信息点。#305894 需要确认哪一步慢、怎样复现或慢多久，两条固定问题都没有涉及这些点。3/4 衡量的是至少覆盖一个信息点。
- **Gemini 在相同候选上作出了 8 条正确的关联或新建建议。** 例如 #251403 与 #241827 都报告接受终端补全后没有插入空格，Gemini 建议关联。在 #248468 中，它区分了 Linux 的 URL 冒号转义与候选 #47816 的 Windows 环境变量未刷新，建议新建。
- **Gemini 在两条信息不足的反馈上建议新建。** #275714 提到了 UNC 路径和运行问题，还需确认失败命令、具体报错及同一命令在本地目录能否运行。#305894 只提到更新后终端变慢，还需确定变慢的操作、复现步骤和耗时。
- **Gemini 在两条反馈上的追问都覆盖了实际缺项。** #262330 询问 Git Bash 启动时的报错或日志，#305957 询问触发崩溃的命令和出现的错误。以全部 4 条参考动作是先补信息的反馈为分母，覆盖数为 2/4。

样例三类各 4 条。4 条关联目标在构建评估库时选入，结果衡量这批冻结样例上的检索和决策。
